## Phase 4: tile names and slides (2026-10-27 night, `feat/phase-4-screen`)
Design: `docs/superpowers/specs/2026-10-27-lyra-phase-4-screen-design.md`. Findings: `docs/notes/phase4-findings.md`.
- **Aidan's choices:** all call apps; tile names fill in **and teach the voice**; slides **off unless switched on**
  per meeting (**Allow + slides**, or the bottom bar's Slides button with its count); slides **linked, not embedded**
  (`slides/` + `slides.json` in the recordings folder; the note's jump line ends ` · [N slides](file:///…/slides/)`,
  `slides: N` in frontmatter; a "N slides" pill opens the folder).
- During a call recording, Lyra reads the call window once a second, in memory only. A lit tile (any hollow
  saturated ring) plus its OCR'd name goes to `onscreen.json`. Processing names still-unknown call voices
  (≥ 6 s, ≥ 75 % one name, one name = one voice) as *on screen* and learns them. Renaming takes the learned
  voice back out.
- The window rule is deny by default: only call-site tabs in browsers, only call-titled windows in desktop
  apps, FaceTime whole. Discord gives no tile names.
- Verified: 465 core + 36 app tests; real Vision on drawn call frames; real ScreenCaptureKit capture of a window
  (gated); end to end on a scratch copy (both test voices named on screen, 3 slides linked). Installed
  2026-10-27 22:4x from the branch with main merged in.
- **Not yet verified:** a real call. Each app's actual ring in Aidan's layouts, the thresholds on real webcam
  and slide motion, and the file:// link opening Finder from Obsidian.
